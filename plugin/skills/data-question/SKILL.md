# 데이터 질문에 답하기

세 가지를 지킨다.
1. **숫자는 쿼리 결과에 있는 것만** 쓴다.
2. **어떤 기준으로 셌는지** 밝힌다(같은 "매출"도 기준에 따라 1위가 바뀐다).
3. **실행한 SQL을 보여 준다.** 사용자가 직접 검증하고 다시 쓸 수 있게.

## 준비

db-scout MCP 도구가 필요하다. `run_query`가 없으면 시작하지 말고 설치 방법을 알려 준다(`/plugin install db-scout@db-scout-mcp`).
접속이 여러 개면 `list_connections`로 확인하고, 어느 DB인지 불분명하면 묻는다.

## 진행 순서

### 1. 질문을 나눈다
- **무엇을** 셀지(지표): 금액 합계? 건수? 고유 고객 수?
- **무엇별로**(묶는 기준): 카테고리별, 매장별, 월별
- **언제**(기간)와 **몇 개**(상위 N)

뜻이 여러 가지인 말은 해석을 정해야 한다.
- "매출": 결제 금액 합계인가, 대여료(가격)의 합인가? 매장별이면 **어느 매장에 붙이는가**(물건이 있던 매장, 결제를 받은 직원의 매장, 고객이 등록한 매장)?
- "인기": 대여 횟수인가, 고객 수인가? "활성 고객": active 컬럼인가, 최근 거래가 있는 고객인가?

가장 자연스러운 해석 하나를 골라 답하고, **답변에 그 기준을 적는다.** 해석에 따라 결론이 뒤집히는 질문이면 다른 기준의 결과도 한 줄 덧붙인다.
어느 해석도 자연스럽지 않으면 먼저 사용자에게 묻는다.

**계산하지 않은 기준에 대해 단정하지 않는다.** "어느 기준으로 봐도 같다", "다른 기준이어도 1위는 그대로다"는 그 기준들을 모두 계산해 본 뒤에만 쓴다.
기준 후보가 두세 개면 모두 계산해 표로 비교한다(매장별 매출이면 위의 세 기준). 계산하지 않은 기준은 "이 기준으로는 확인하지 않았다"고 쓴다.

### 2. 테이블과 컬럼을 찾는다
구조를 모르면 `search_schema`(영어 이름·줄임말·한국어를 함께) → `describe_table`. 대화에서 이미 본 구조는 다시 묻지 않는다.
뷰(예: `sales_by_store`)가 질문에 딱 맞아 보여도, 그 뷰가 어떤 기준으로 계산하는지 모르면 원본 테이블로 직접 계산한다.

### 3. 조인 조건은 도구로 확인한다
테이블 두 개 이상을 이으면 `find_join_path`로 경로와 조건을 확인하고, 돌려준 `FROM ... JOIN` 절을 그대로 쓴다.
조인 조건을 컬럼 이름으로 추측하지 않는다. 경로가 여러 개면 질문 뜻에 맞는 것을 고르고 답변에 밝힌다.

### 4. 조건에 쓸 값의 모양을 먼저 본다
값의 모양을 모르면 `profile_column`이나 `sample_rows`로 확인한 뒤 WHERE를 쓴다.
- 날짜 조건 전에는 최소·최대로 **데이터가 있는 기간**을 본다. 묻는 기간에 데이터가 없으면 그렇다고 알린다.
- 상태·코드 값은 실제 값(대소문자, 숫자/문자)을 확인한다.

### 5. SQL을 쓴다
- **집계는 SQL 안에서** 한다(GROUP BY, COUNT, SUM). 행을 많이 가져와 직접 세거나 더하지 않는다.
- 상위 N은 `ORDER BY ... DESC LIMIT N`. 경계에 동점이 있으면 알린다.
- `list_connections`의 type(SQLite, MySQL, PostgreSQL)에 맞는 날짜 함수를 쓴다.
- 큰 테이블을 여러 개 잇거나 오래 걸릴 것 같으면 `explain_query`로 먼저 확인한다.

### 6. 실행하고 점검한다
`run_query`로 실행한다.
- 오류가 나면 메시지를 읽고 고쳐서 다시 실행한다. 같은 SQL을 반복하지 않는다. 두세 번 안에 안 되면 무엇이 문제인지 사용자에게 설명한다.
- `truncated: true`면 결과가 잘린 것이다. 잘린 결과로 결론 내지 말고 집계 쿼리로 다시 묻는다.
- 결과가 상식과 맞는지 본다(부분 합이 전체보다 큰가, 0행인가, 중복으로 부풀지 않았나).

## 답변 형식

1. **첫 줄에 답**: 핵심 숫자·이름을 굵게. 예) "매출 1위 카테고리는 **Sports(5,314.21)**입니다."
2. **표**: 여러 행이면 상위 10행까지.
3. **기준**: 예) "매출 = 결제(payment.amount) 합계, 대여된 DVD의 카테고리 기준"
4. **실행한 SQL**: ```sql 코드 블록.
5. 결과가 잘렸거나 가려진 컬럼이 있으면 한 줄로 알린다.

숫자는 결과 그대로 쓴다. 반올림하면 "약"을 붙인다.

## 하지 않는 것

- **데이터를 바꾸는 요청**(수정·삭제·추가)은 `run_query`로 시도하지 않는다. 이 서버는 읽기 전용이라 실행할 수 없다고 설명한다.
  사용자가 원하면 **직접 실행할 SQL**을 보여 줄 수 있다. 이때 영향받을 행 수를 SELECT로 먼저 세어 알려 주고, 실행 전 백업과 WHERE 조건 확인을 권한다.
- **가려진 개인정보를 우회하지 않는다.** 이메일·전화번호·이름 등이 가려져 나오면 그대로 전한다.
  함수·문자열 연결·조건 반복 등으로 원래 값을 알아내려 하지 않는다. 원래 값이 필요하면 권한 있는 담당자가 DB에서 직접 확인해야 한다고 안내한다.
  가려진 값이 있어도 개수·순위 같은 답은 그대로 줄 수 있다(예: 고객 번호와 대여 횟수).
- **전부 보여 달라는 요청**(예: "대여 기록 전부")에는 전체를 쏟아내지 않는다. 전체 건수와 기간을 먼저 알려 주고, 요약(월별·상위 N)이나 조건을 제안한다.
- 결과에 없는 숫자를 만들지 않는다.
